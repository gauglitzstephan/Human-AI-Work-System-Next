# ADR-0002 — Adaptive Work-Control without a peer Work Engine

**Status:** PROPOSED FOR Δ4 CLOSURE  
**Date:** 2026-08-19  
**Decision scope:** architectural placement of the historical Semantic Compiler / Adaptive Work-Control concept.  
**Not in scope:** final runtime wording, Custom Instructions, agent implementation, or behavioral superiority of any deployed configuration.

---

## Context

The predecessor `Human-AI-Work-System` introduced a `Semantic Compiler` as an orchestration policy for selecting a minimum sufficient next-work frontier from current state, requirements, blockers, capabilities, authority, consequence and uncertainty.

The bootstrap lineage review established that:

- qualified Work Architecture already owns outcome/work formation, authoritative reality, professional method, conditional Work Units, Human–AI composition, state/authority, assurance, realization, local reopen and proportional closure;
- PAOS already supplies a strong minimum-complexity routing counter-design;
- a peer `Work Engine` layer has no distinct ownership basis.

Δ4 therefore asks only whether the **incremental control functions** attributed to the Semantic Compiler justify separate architectural promotion.

---

## Evidence considered

### Qualified prior architecture

`AI-native-Operating-Model` Work Architecture already contains most adaptive work semantics later associated with the Compiler.

### Pre-Compiler whole-task behavior

The v0.3.4 whole-task suite showed strong/direct behavior on bounded work, current-evidence decision work, existing-state repair and readiness calibration before the explicit B.6 Semantic Compiler line.

### B.6 real-use evidence

B.6 canaries and ordinary-use observations are directionally positive, but the treatment combines many changes and cannot isolate the Semantic Compiler as the causal mechanism.

### Negative controller/gate evidence

The earlier `Pre-Commitment Gate` experiment failed its first consequential decision case and was stopped because further context-poor trigger testing had low information value.

### Runtime/salience evidence

The v0.6.1→v0.6.2 history shows that the active semantic budget is finite. New decision-edge wording competed with historically necessary high-salience Work Product, alternative-breadth and next-use-maturity functions and required semantic recompilation.

### External reference synthesis

Rational metareasoning supports selecting computations based on their expected value/cost. Costly-learning and optimal-stopping research supports considering learnability, information quality/cost and when to stop learning. Robust Decision Making supports robust/adaptive strategies under deep uncertainty rather than fabricated precision. Real-options research supports staged/reversible commitment when flexibility and learning have positive value, while also showing that flexibility is not universally beneficial.

These references support the **individual conditional policies**. They do not establish that a universal Human–AI Work Controller should own them all.

Relevant anchors:
- Callaway et al. (2017), `Learning to select computations`: https://arxiv.org/abs/1711.06892
- De Sabbata, Sumers & Griffiths (2024), `Rational Metareasoning for Large Language Models`: https://arxiv.org/abs/2410.05563
- Harrison & Sunar (2015), `Investment Timing with Incomplete Information and Multiple Means of Learning`: https://doi.org/10.1287/opre.2015.1344
- RAND Robust Decision Making example: https://www.rand.org/content/dam/rand/pubs/research_reports/RR2900/RR2931/RAND_RR2931.pdf
- Childs & Triantis (1999), `Dynamic R&D Investment Policies`: https://doi.org/10.1287/mnsc.45.10.1359
- Chavda (2023), `Which Types of Investments Benefit from Retaining the Flexibility to Terminate?`: https://doi.org/10.1287/stsc.2021.0095

## Decision

### D1 — Do not promote a peer `Work Engine`

```text
Work Engine as new top-level responsibility layer/subsystem
→ REJECT
```

No unique responsibility remains that is not already owned by Work Architecture, other responsibility layers, Views/Integrity Contracts, or runtime realization.

### D2 — Do not promote the full Semantic Compiler bundle as a distinct architecture responsibility

```text
Full Semantic Compiler
→ DO NOT PROMOTE as separate architecture object
```

Most of its historical inputs/outputs are already qualified Work Architecture semantics.

The label may remain useful as:
- an explanatory model;
- a semantic-compilation metaphor;
- historical Knowledge Capital;
- a candidate runtime realization pattern.

It does not receive independent ownership merely because it compresses several mechanisms into one diagram.

### D3 — Retain a thin conditional Adaptive Work-Control metapolicy inside Work Architecture

The only incremental policy family worth retaining conceptually is:

```text
NEXT STATE
→ what exact decision/claim/state transition matters next?

LEARN
→ if a decision-flipping unknown is learnable and worth acquisition/delay/coordination cost

ROBUSTIFY
→ if material uncertainty cannot/should not be resolved, stress-test vulnerabilities and retain useful signposts

COMMIT
→ choose commitment depth from wait/pilot/stage/reversible/information-generating/full commitment according to learning/option value and cost

STOP
→ stop additional cognition/flexibility when it can no longer change the decision enough to justify cost
```

Architectural type:

> **conditional Work-Control / metareasoning policy inside Work Architecture**

not:

> subsystem, lifecycle, agent, mandatory state machine, or peer architecture layer.

### D4 — Detailed decision machinery remains method/capability Knowledge Capital

Do not encode detailed:
- quantitative Value of Information;
- forecasting;
- scenario construction;
- Robust Decision Making;
- real-options valuation;
- experimentation/pilot design;

inside a universal controller.

These remain conditional professional/decision methods selected when the Work Object requires them.

### D5 — No global runtime promotion is established by Δ4

The thin metapolicy is **conceptually retained**, but Δ4 does not establish that its explicit wording belongs in a global runtime.

That question moves to Δ5:

> Which load-bearing semantics require explicit active salience, retrieval, Skill/method activation or deterministic enforcement in a finite runtime/context?

---

## Why no new behavioral suite is required to make this conservative decision

Architecture promotion has an asymmetric burden:

```text
candidate wants additional global semantic responsibility
→ candidate must show incremental value

candidate lacks incremental evidence
→ default is non-promotion
```

The existing evidence does not justify full/global promotion.

A bespoke behavioral ablation would be necessary to justify a **stronger** decision — for example promoting the thin metapolicy into a global runtime invariant — but is not required to decide against that stronger claim now.

The exact matched whole-task design is preserved in:

`evaluation/DELTA-04-WHOLE-TASK-ABLATION-DESIGN-v0.1.md`

Use it as a **reopen instrument**, not the default next step.

---

## Consequences

### Positive

- avoids a redundant Work Engine layer;
- preserves the useful decision-edge mechanisms;
- keeps Work Architecture ownership coherent;
- prevents detailed foresight/VoI/options methods from becoming universal ceremony;
- reduces architecture/runtime semantic burden;
- allows future evidence to promote only the policy that actually earns value.

### Costs / risks

- capable models may under-activate Information Value, Robustness or Commitment Design when those policies remain implicit/conditional;
- the `next legitimate state` / minimum-frontier framing may have useful compression value that is not behaviorally isolated yet;
- demoting explicit compiler centrality may lose salience in a future runtime if Δ5 does not preserve a suitable activation route.

These are Δ5/runtime risks, not evidence for a new Δ4 architecture owner.

---

## Reopen triggers

Reopen Δ4 if any of the following occurs:

1. repeated real-use failure where A-style Work Architecture performs unnecessary work/research because no explicit metapolicy activates;
2. repeated premature commitment that would likely have been prevented by the thin policy;
3. repeated forecast/uncertainty misuse that a robustness-routing policy prevents;
4. matched A↔B whole-task evidence shows reproducible material improvement with acceptable directness/context cost;
5. a future model/runtime architecture makes an explicit next-state controller materially cheaper or more reliable;
6. Δ5 shows that semantic compilation requires an explicit controller object to preserve behavior across runtime surfaces.

## Proposed Δ4 closure

```text
Peer Work Engine                         REJECT
Full Semantic Compiler architecture     DO NOT PROMOTE
Semantic Compiler explanatory model     RETAIN AS KNOWLEDGE / POSSIBLE RUNTIME PATTERN
Thin Adaptive Work-Control metapolicy   RETAIN CONDITIONALLY INSIDE WORK ARCHITECTURE
Detailed VoI/RDM/Real Options methods   CONDITIONAL METHOD / CAPABILITY KNOWLEDGE
Global runtime activation               OPEN → Δ5
Behavioral A/B suite                     DEFER / REOPEN INSTRUMENT
```

If this ADR is accepted, Δ4 closes and the next architecture delta is **Δ5 — Architecture → Runtime Semantic Compilation**.
