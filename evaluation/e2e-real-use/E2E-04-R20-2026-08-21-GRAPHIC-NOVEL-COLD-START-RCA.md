## 1. Actual real-use basis

This case uses a genuine creative/professional initiative: development of a long-form historical Graphic Novel about the history of beer.

Primary source material supplied by the Human:

- original Graphic-Novel work conversation: `https://chatgpt.com/share/6a88169d-3d6c-83eb-8a2f-b462d0edacf0`;
- immediate behavioral review / collaboration audit: `https://chatgpt.com/share/6a8816be-7d90-83ed-822d-2c3753d61baf`;
- conversation snapshots supplied into the System Development validation chat and reviewed against the authoritative repository architecture/runtime state.

The original work produced increasingly specific narrative constructs including:

```text
Human Continuity × Expanding Understanding
Chain of Hands
Hidden Partner
Echoing Glass
Choral Relationship Relay + Silent Hidden Partner
```

Several of those constructs may be substantively useful. This RCA does not judge them invalid merely because upstream orchestration failed. The failure claim concerns **when and on what professional basis substantive solution/candidate work was admitted and qualified**.

## 2. Raw trigger / work reality

The initiating work object was materially open and plausibly persistent:

> develop a Graphic Novel about the history of beer.

Material characteristics visible at cold start:

- long-horizon creative initiative rather than a bounded one-shot answer;
- open narrative problem and solution class;
- professional craft dependence: long-form narrative architecture, sequential-art storytelling, historical narrative, exposition/information integration, visual grammar;
- material historical/reference-intelligence dependence;
- likely persistent state/continuity need across work episodes;
- large solution space in which unresolved upstream variables could materially change solution class and evaluation.

The observed Runtime nevertheless entered substantive story architecture rapidly and later used semantic labels such as `Candidate`, `strongest candidate` and `qualified` before a sufficiently explicit professional Performance/Reference/Method basis had been established.

## 3. Human-observed failure signals

The subsequent behavioral review identified two visible failure families.

### A. Parent / Bigger-Picture legibility

State banners improved local orientation (`State`, `Next Frontier`, `Disposition`) but did not consistently expose the controlling Parent Work Object / bigger-picture outcome and why the active child work mattered to it.

### B. Premature substantive solution / candidate admission

The more fundamental defect was upstream: substantive Story Architecture work was admitted before the work object had been formed enough to establish the relevant professional performance problem, decision-changing unknowns, craft/reference basis and persistence/context need.

The Human had to detect and redirect this AI-resolvable upstream control defect. That is negative Human-burden evidence under the R20 validation protocol.

## 4. Differential trace

The failure was traced across:


### 4.1 Initial Parent / Work-Object bootstrap

**Requirements / architecture:** ownership exists. CR-01, CR-02, CR-08 and Adaptive Work Selection require enough outcome/scope/reality/work admission to select legitimate next work. The E2E Work Architecture begins `REALITY / TRIGGER → ADMIT + FRAME → FORMATION`.

**Operating Runtime:** continuation is strongly represented through `REBIND parent Work Object / outcome + current state/gate + child contribution + allowed operation`. Formation exists, but the asymmetric case in which a **new material Work Object has no established parent/state yet** is not compiled into an equally explicit cold-start operation.

**Canonical / Global:** `Bind parent ... unclear→recover` remains continuation/recovery oriented. It does not explicitly state what to establish when the Parent/Work System does not yet exist.

**Observed behavior:** the new professional initiative was treated too much like ordinary bounded generative Chat.

**Localization:** **Runtime composition / activation gap**. No new static owner is demonstrated missing.

### 4.2 Solution / Candidate admission

**Requirements / architecture:** CR-10 explicitly states `minimum work` must not permit material stage/dependency collapse. Downstream transformation may begin only when materially required upstream state/Work Products are sufficiently ready. The E2E Work Architecture places Formation before `DECISION-READY CANDIDATE` and requires Purpose/Outcome, Requirements/Performance, Professional/Reference Intelligence and relevant evidence/uncertainty as part of that readiness.

**Operating Runtime:** the strong explicit guard is mainly against **route commitment** while a material upstream dependency that could flip the route remains untreated.

**Canonical / Global:** FORM-06 / `FORM+DECIDE` preserve commitment readiness and ends-before-means, but no equally explicit guard says that early solutions generated while materially decision-changing upstream state remains open are only probes/hypotheses and must not yet receive qualified Candidate/design-basis status.

**Observed behavior:** `unpromoted` was used correctly, but the work crossed an earlier semantic boundary: **not promoted ≠ legitimately candidate-ready**.

**Localization:** **material Architecture→Runtime semantic-preservation gap in Solution/Candidate Admission**; currently a Runtime-realization failure, not an unowned Target-Architecture responsibility.

### 4.3 Professional / Reference Method activation

**Requirements / architecture:** CR-05 and the E2E Work Architecture explicitly require an applicable professional performance bar and Professional/Reference Intelligence where material.

**Operating Runtime / canonical / Global:** Method Activation is present and supports task-local method/reference resolution when no reusable pack exists. An already-prepared Graphic-Novel Method Stack is not a prerequisite.

**Observed behavior:** no material narrative/sequential-art/historical-storytelling method/reference resolution activated before substantive story-architecture generation. Latent model priors effectively substituted for explicit professional craft intelligence.

**Localization:** **behavioral Runtime non-conformance / Method-trigger failure**. Missing prebuilt domain method pack is not the Root Cause.

### 4.4 Persistent initiative / context activation

**Requirements / architecture:** CCR-02, Distributed Typed State and Operating Responsibility already own persistent/divergent-state handling. Project is one possible persistent initiative/context carrier, not a universal prerequisite.

**Runtime:** state/persistence semantics exist, but cold-start detection of the point at which transient chat should become a persistently bound initiative context is not strongly composed with Admission/Formation.

**Observed behavior:** the conversation itself remained the practical state carrier too long; persistent narrative-state ownership was only recognized later in review.

**Localization:** **Runtime activation/composition gap**. `Missing Project` is rejected as Root Cause.

### 4.5 Human-facing Parent legibility

**Architecture / requirements:** Parent continuity and shared-state legibility already exist.

**Canonical / Global:** BC-06 / Human-facing Control Return exposes achieved state, persistence/promotion, next frontier/actor, Human contribution and disposition. The controlling Parent/bigger-picture outcome is not itself an explicit minimum Human-facing field.

**Observed behavior:** improved state banners still left the Human missing the bigger-picture Parent relation.

**Localization:** **separate Runtime Control-Return legibility gap**. It is material but not the primary cause of premature substantive work.

## 5. Compilation-assurance finding

The existing compiled semantic trace marks broad groups such as `WF-01–11`, `FORM-01–06`, `MET-01–07` as `EMBEDDED` in Global v0.5.

R20 shows that this style of trace is insufficient for at least one failure mode:

> **semantic labels/functions may all be present while the material relational guard between them is weakened or lost.**

The relevant lost/weak relation is approximately:

```text
new material trigger
→ admit/frame/initial work-object formation
→ sufficient upstream Performance/Reference/State readiness?
→ if materially open, early solution = probe/hypothesis
→ qualified Candidate/design basis only after readiness floor
```

This is consistent with the Canonical Compilation Contract's own rule that a high-level label is not a mechanism PASS and that material semantics must be reallocated rather than silently dropped.

**Assurance implication:** future Runtime compilation review must test material **activation/transition relations**, not only ID/label presence.

### Strongest Root Cause
