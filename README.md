# Human–AI Work System Next — Rebaseline Candidate

This repository is being reduced from a custom ChatGPT runtime into a smaller evidence- and method-oriented support layer around native ChatGPT.

**Branch status:** `rebaseline/native-delta-2026-09-02` is a candidate. `main` remains historical promoted state until this rebaseline is explicitly accepted and merged.

## Start here

Read [`CURRENT.md`](CURRENT.md).

The current rebaseline hypothesis is:

> **Native ChatGPT + current Global CI + actually available professional providers/methods + narrowly justified reusable methods + domain-owned authority/persistence + proportional claim-matched assurance.**

The objective is professionally useful work, not process compliance or preservation of prior architecture.

## What changed in the rebaseline

The effective 2026-09-02 ChatGPT Global CI has diverged from the old compiled repository Runtime. Explicit repo-local Skill routing, QWS/runtime orchestration, lifecycle/closure control, provider registry and surface routing were deliberately removed from the active Global CI.

Genuine-use failures then showed two things simultaneously:

1. the old custom Runtime could narrow or distort native/provider behavior;
2. important semantic learnings from the old system remain valuable, especially reality grounding, actual-state recovery, qualified reuse, professional sufficiency, Human agency, authority/state distinctions, minimum-sufficient work and claim-matched assurance.

The rebaseline therefore preserves the learnings while demoting the old implementation.

## Durable learning record

The main extraction is [`rebaseline/DURABLE-LEARNINGS-SEPARATION-2026-09-02.md`](rebaseline/DURABLE-LEARNINGS-SEPARATION-2026-09-02.md).

It explicitly separates durable semantics from implementation choices. Key examples:

- request/proposed means ≠ complete specification;
- reality outranks plausibility;
- recover relevant actual state before substantial/consequential work;
- requalify prior work before reuse;
- coherence ≠ professional completeness;
- professional method matters where validity depends on it;
- native capability should not be redundantly rebuilt;
- capability/access/effectiveness/Authority/accountability are distinct;
- working context ≠ authoritative state ≠ reusable knowledge;
- relevant context beats maximal context;
- Human attention is a system cost;
- meta-work must not replace the requested Work Product;
- produced ≠ fit ≠ used ≠ effective ≠ valuable;
- assurance must be able to detect the claimed failure.

## Current evidence

The 2026-09-02 rebaseline is grounded in actual failures including:

- repository/effective-runtime drift;
- provider-space narrowing from repo-local routing;
- incorrect inference of product/surface unavailability;
- provider-repair work built against a stale carrier;
- Sika application production that ignored accessible prior work, references and known failure lessons;
- poor CV repair that reproduced legacy craft/layout problems;
- technical generation/rendering incorrectly treated as professional fitness;
- repeated meta-work displacing the Human's requested outcome.

## Change boundary

This branch is deliberately conservative:

- historical files are not deleted merely because their Runtime role is obsolete;
- obsolete authority is removed before history is removed;
- the effective current CI is not silently rewritten from repository history;
- Personal Skill uninstall/removal is a separate decision;
- merge to `main` requires explicit Human acceptance.

The immediate goal is a coherent repository that no longer tells future work to treat the obsolete Runtime as current.
