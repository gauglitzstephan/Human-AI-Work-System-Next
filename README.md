# Human–AI Work System Next

A small support layer around native ChatGPT for professionally useful work. It preserves validated work principles, one compact native-transition contract and a few genuinely differentiated reusable methods; it is not a custom ChatGPT runtime.

## Start here

Read [`CURRENT.md`](CURRENT.md). It is the only repository-state entry point.

The operating hypothesis is:

> **Native ChatGPT + current Global Custom Instructions + actually available professional providers/methods + narrowly justified reusable methods + domain-owned authority/persistence + proportional claim-matched assurance.**

Only three custom Skills remain in the active repository portfolio:

- `decision-analysis` — bounded material choices under objectives, uncertainty, downside and option value;
- `evaluate-work-product` — recipient/use/failure-mode-capable fitness evaluation;
- `system-development` — recovery, diagnosis, semantic preservation, promotion/readback and genuine-use evaluation for this system.

They are optional method providers, not stages or a complete provider universe. Native or installed specialist providers take precedence when they fit better.

## Native Chat ↔ Work cooperation

Chat or Project context is the default joint thinking and formation space. When a material Work Object is sufficiently formed and Work or another native surface would materially improve execution, use the compact transition contract:

```text
qualified Work Object
+ proportionate Work Architecture
+ qualified context / authority / assurance / return
→ native planning and execution
→ Work Product + qualified return
```

The receiving native runtime owns operational planning, decomposition, provider/tool use and execution within the handoff. Human/domain owners retain material judgment, commitment, release and authoritative persistence.

This is conditional and collapses for bounded work. It is not a universal Work Contract, graph, lifecycle or surface router.

## What ChatGPT owns natively

Native ChatGPT owns ordinary conversation, reasoning, planning, capability selection and integration, context/tool use and product-surface behavior. Chat, Work, Projects, Skills, plugins/apps/connectors, research, files/artifacts, GitHub and other execution systems belong to the available capability space.

This repository does not recreate a Semantic Compiler, global provider/surface router, universal QWS, Work Graph, lifecycle/closure state machine, central state store or mandatory meta-work layer.
