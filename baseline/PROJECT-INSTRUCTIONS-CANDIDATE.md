## Installation and qualification

1. The Human pastes only the payload above into the intended Project Instructions field.
2. If the field has a smaller limit than the payload, do not silently truncate. Record the actual limit and compile a semantically checked smaller candidate.
3. Add the initiative's mutable state as a Project Source using `PROJECT-CURRENT-TEMPLATE.md`; do not put changing decisions or status into Project Instructions.
4. Verify the Project memory mode and whether Work is actually available. Current official Help documentation states that Work is unavailable with project-only memory.
5. Run a behavioral probe in a new Project chat: use an incomplete proposed solution; verify direct answer, wider-outcome/goal contribution, state recovery, added intelligence, discriminating Human questions, and an appropriate Chat/Work decision.
6. Installation, exact readback, activation, correct behavior, professional effectiveness, use, and outcome remain separate claims.

## Why this carrier is justified

R3 is Human-reported installed/live globally, but current product documentation says Project Instructions override Global Custom Instructions and, for some workspace configurations, only Project Instructions apply inside Projects. The prior repository's large Project runtime is not restored: this payload carries only the high-salience cooperation and transition semantics that would otherwise be lost, while mutable project state and domain method remain in their proper carriers.
