**Status:** repository Candidate, 6 September 2026. This is the practical entry point. Its supporting basis is the [Requirement Master](../inventory/REQUIREMENT-MASTER-2026-09-06.md), [operating realization](HUMAN-AI-WORK-OPERATING-REALIZATION.md), and [reconciled evidence](../inventory/RUNTIME-REALIZATION-RECONCILIATION-2026-09-06.md). ## What to do tomorrow

Begin with the actual situation and whatever material you already have. You can say “We keep answering the same questions; perhaps we need a chatbot,” “I have an interview and don't know what they really need to see,” or “These reports disagree; help me understand what matters.” Do not prepare the system's requirements or select a sequence of methods first.

Use Chat when short exchanges are the convenient way to progress. Use Work directly when useful progress involves sustained investigation, methods, tools, analysis, integration or production. **An unfinished problem is a valid Work opening.** Its first valuable result may be a better goal or explanation, rather than an artifact. Both environments should contribute Joint Intelligence: notice something, develop a useful model or question, challenge a material premise, and integrate your correction. Neither environment is assigned exclusive ownership of cognition.

Use a Project for an initiative that will continue across outputs and conversations with recurring sources. Stay outside Projects for self-contained or short-lived professional work. When an existing conversation becomes serious, it does not need a ceremonial restart. ChatGPT should recover its qualified state, improve the next contribution, and recommend a change of environment only when that change earns the transfer burden.

Your contributions are situated context, values, expertise, taste, judgment and legitimate authority when those matter. ChatGPT should prepare a mature question, contrast or decision object before asking. You can correct it directly: “The concern is workload, not reporting consistency,” “Keep that requirement,” or “This is a probe, not a build decision.” A correction should change the affected model and conclusions, while preserving unrelated work. “Next” continues the agreed contribution to the parent outcome.

R3 is already Human-reported live. Do not reinstall it as an ordinary work step. The repository's full text does not automatically influence every chat. In a Project that uses Project Instructions, the essential cooperation instructions need their own carrier. The exact [Project payload](PROJECT-INSTRUCTIONS-CANDIDATE.md) is ready for separate acceptance/installation; mutable initiative state goes in a source, not in that standing payload.

## Environment selection without a personal routing job

| Situation | Operating choice | What ChatGPT resolves | Your deliberate action, if needed |
|---|---|---|---|
| A one-off question becomes serious | Continue in the current chat while useful; suggest Work for sustained contribution | Recover parent, expose a consequential premise, supply a useful next answer, compile any handoff | Supply inaccessible context; open Work and paste the compiled brief only if transfer is unavailable |
| Multi-turn non-Project work | One conversation plus a compact checkpoint when continuity risk becomes material | Carry decisions/rejections, reconcile corrections, save a versioned checkpoint through an available authorized route | Move/attach the prepared checkpoint to a new conversation if needed |
| Persistent Project initiative | Project Chat and eligible Project Work; one curated current-state source with exact external pointers | Recover relevant source sections, check freshness/conflicts, maintain the useful state delta | Configure the Project once; save the AI-prepared source if no source-write tool is available |
| Research-heavy work | Bounded search in Chat; Work or deep research for sustained inquiry, with a domain method when required | Form the evidence questions, select sources/method, seek counterevidence, synthesize and qualify limits | Supply inaccessible sources, approve relevant access; steer substantive direction |
| Material decision | Chat or Work according to effort; decision-analysis inside Work when its method adds value | Identify decision level/owner, develop viable options, evidence, trade-offs, uncertainty, rival and switching conditions | Supply genuine preferences and make/authorize the consequential decision |
| Professional artifact | Work with the actual document, slides, spreadsheet, design or code method | Infer recipient/use requirements, retrieve exemplars, produce, render/test and refine the product | Supply tacit taste/authorship and judge acceptance/release; do not act as the routine defect detector |
| Long-running operational initiative | Project if helpful, but exact operational state stays in its domain store | Read current source before action, resolve deltas, perform authorized writes/readbacks and preserve recovery | Grant scope/access and retain decisions outside delegation |
| Work output returns to a parent | Continue in the same Work episode if it is the parent; otherwise return a compiled product/state package | Rebind parent, reconcile changes and conflicts, preserve rejected directions, save only the earned state class | Mechanical return copy if needed; judge real conflicts or acceptance |

Current product-specific limits matter. Project Instructions override Global CI; this does not prove that every nonconflicting global instruction is suppressed in every plan. Carry essentials explicitly rather than relying on undocumented merging. Project-only memory currently makes Work unavailable in that Project. If isolation is necessary, keep that setting and use a deliberately limited portable Work package outside the Project, or remain in Project Chat if it has the necessary capabilities. Do not change privacy isolation merely for convenience. Project context and retrieval remain selective. [OpenAI Projects Help](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt)

Work supports interaction and steering during sustained work. There is no evidence here that ordinary Chat is uniquely capable of collaborative formation, or that Work requires a finalized goal. Likewise, documented support for Chat and Work in a Project does not prove automatic conversion of an existing chat with all context. [Work guidance](https://learn.chatgpt.com/docs/long-running-work), [Projects guidance](https://learn.chatgpt.com/docs/projects)

## A complete example: incomplete situation to return

The following is a **fictional operating example**, not evidence about the Human's organization or a performed research result.

**Natural opening, in Chat or Work:** “Our specialists keep answering the same questions. Maybe we should build a chatbot.”

**Useful AI contribution:** “The repeat questions may be four different kinds of work: finding an approved answer, interpreting a policy, teaching a newcomer, or diagnosing an unusual incident. A chatbot could help some and make others less accountable. The worthwhile outcome may be correct answers with less avoidable expert effort. Is that the concern, or is speed of response the larger problem? I can first inspect the available cases and existing knowledge sources.”

This both adds a causal distinction and poses a better question. It does not ask you to fill out the whole work brief. ChatGPT recovers accessible cases before requesting information you already supplied.

**Human contribution:** “Accuracy and accountability come first. People also need to learn. We have 20 anonymized cases and an existing wiki. Do not contact anyone or build anything yet.”

**Adaptive next contribution:** ChatGPT inspects the cases and source permissions if accessible, distinguishes observed categories from inference, and tests whether “repetition” actually means unnecessary work. It can compare retrieval/stewardship, accountable interpretation, onboarding/prevention and incident diagnosis as different mechanisms. It uses revised formation or exploration in Work only if that method adds value; you do not need to name either.

**Deliberate transition, if this began in Chat:** “The next useful contribution is a case-based recommendation about which work is avoidable and which intervention is worth testing. Sustained case/source review and integration make Work useful. I have compiled the brief below from our shared state. It preserves the no-build boundary and leaves the solution open.” If this began in Work, continue there without manufacturing a handoff.

**AI-generated professional Work brief:**

> Develop an evidence-backed recommendation for reducing avoidable specialist effort while preserving correct, accountable answers and employee learning. A chatbot is a proposed means, not a chosen solution. The decision owner is the Human; no solution or investment is accepted.
>
> Use the attached 20 anonymized cases and the linked existing permissioned wiki. Confirm which files and wiki sections are accessible before relying on them. Treat the sample's representativeness, time costs and any inferred answer categories as unverified until examined. Keep original source identifiers in the evidence record. Do not infer permissions or policy authority from a retrieved answer.
>
> Determine what is actually happening, the useful goal and decision level, and which repeated work is avoidable. Distinguish lookup, accountable interpretation, learning gaps and diagnosis only if the evidence supports those distinctions; allow other explanations. Compare mechanism-distinct interventions, the existing process/no action, reuse, staged approaches and a reversible test. Do not score weak qualitative evidence with invented weights or promise savings without a credible basis.
>
> Work may recover context, research, form/explore the problem, choose relevant methods and tools, revise hypotheses and produce local reviewable artifacts within scope. Use a narrower knowledge-management or domain method if the claim needs it. The optional formation/exploration methods may help; no prescribed Skill sequence is required.
>
> Produce a concise recommendation with a case-to-finding trace, explicit evidence/assumption boundaries, the strongest rival, and a discriminating test proposal with success, stop and switching conditions. Explain the effect on expert effort, accountability, employee learning and maintenance. Test the recommendation against actual case exceptions and access constraints. A proposed offline replay is not a completed replay or proof of savings.
>
> No build, contact, publication, spending, permission change or authoritative policy edit is authorized. Prepare any needed Human decision as a concrete object. Return the recommendation, actual sources/methods and checks, unresolved limits, proposed state delta, and next useful contribution to this parent concern. Preserve all corrections and rejected directions. Save working outputs through the available authorized file route; do not promote them to accepted policy or reusable knowledge.

In actual use, ChatGPT inserts the known exact source links, filenames, versions and qualified findings. It must not replace those with these example phrases or ask the Human to reconstruct them. A full brief is justified here because multiple sources, methods, protected effects and return obligations matter. A short factual lookup does not need it.

**Human correction of the brief:** “Also protect specialist availability for unusual incidents. Do not aim to eliminate all repeat questions.”

**Required AI response:** incorporate this in the objective, option comparison and test criteria; preserve accurate answers, learning and no-build constraints. Treat necessary expert involvement as a possible success condition. If Work is already running elsewhere, provide the exact correction and dependencies as a portable delta; do not assume the other chat received it.

**Illustrative Work return:** “The recommendation and case trace are ready for review. The evidence supports separating several kinds of demand; it does not establish hours saved or justify a chatbot build. The proposed next commitment is an offline replay with current permissions and accountable owners preserved. Here are the exceptions that could invalidate the recommendation, the actual checks performed, and the open sampling/time-cost assumptions.” This is an example of an appropriately bounded return, not a preselected substantive answer.

**State reintegration:** ChatGPT compares the return with the parent brief and correction. The current working state now records the recommendation, evidence pointers, unsupported savings claim, rejected blanket automation, no-build boundary and proposed replay. It does not record “chatbot approved.” If the Human accepts the replay and authorizes it, that specific decision is recorded through the legitimate path. Only later observed use can support an outcome claim.

## Exact persistence operations

Persistence is a work responsibility, not a requirement that you maintain a second information system.

| Place | What belongs there | What does not gain authority there | Update and recovery operation |
|---|---|---|---|
| Conversation | Working reasoning, hypotheses, useful questions, corrections, immediate decisions and open work | A conversational statement is not automatically accepted or operational truth | AI carries it forward; on long context, interruption or handoff risk, compile a checkpoint with parent, current contribution, protected state, sources, decisions/status and next step |
| Project | Organization and scoped continuity across related work | Membership does not make every source current or every retrieval complete | AI uses relevant Project context, cites the controlling source and checks conflicts; Human chooses membership/settings when UI actions are needed |
| Project Source | Curated working-state view; source documents, explicit current pointer and version/status | A saved response or uploaded file is not automatically approved policy | AI prepares a replacement or delta. Use an available authorized source-write route; otherwise deliver the ready-to-save response/file for the Human's Save to Project or add/replace-source action. Do not claim this UI write occurred |
| Memory | Appropriate enduring preferences and personal context, with sensitivity and scope considered | Exact requirements, approvals, mutable operational status, complete audit history | Correct/restrict/remove through supported controls when material; retrieve authoritative sources for exact reliance. Memory can be partial and automatically synthesized |
| External/domain store | The legitimate record for each operational domain: CRM, approved policy, task status, financial record, repository, etc. | Local copies, reports and chat summaries are derived | Read the current version; compare the intended delta; check existing authorization; write through the legitimate path; read back exact changed fields/version. Stop on unresolved material conflicts, not every harmless edit |
| Accepted Knowledge Capital | Qualified reusable cases, patterns, methods and outcome evidence, with applicability and limits | Successful production or local preference does not establish transferable method value | AI proposes a scoped learning with evidence, owner, applicability, invalidation/review condition and source; promote only with legitimate acceptance/delegation; revise or retire on invalidation |

For important changes, use the latest accessible state at the write boundary. If two Work episodes produce competing edits, compare both with their common baseline; retain nonconflicting changes and expose only real conflicts. A timestamp identifies recency, not correctness. Record which source supersedes which, preserve necessary history and repair dependent outputs. One store is authoritative **per state domain**; the entire initiative need not fit in one store.

The AI may save authorized working drafts without a new acceptance gate. Saving does not itself change maturity. It should proactively prepare a checkpoint when continuity risk warrants one, and actually persist it when a legitimate tool path and authorization exist. Where product UI is the only route, the residual Human work is one mechanical save/copy of an already-complete object. It must say what was prepared versus saved and return a usable source pointer after verified saving.

On resume, retrieve the current pointer, check source versions and unresolved deltas, then continue the controlling parent. If retrieval fails, use a named fallback or request the smallest missing artifact. Do not reconstruct an imagined state or ask for everything again. A Project Current source is optional; use an existing suitable current record rather than creating a duplicate ledger.

For delayed outcomes, define the useful observation, source, owner and response condition. Automations may perform a bounded recurring check, but only with actual source access, permissions and a stop/reconciliation rule. Current scheduled tasks cannot access uploaded or Project-stored files even when created in a Project; do not use “monitor the Project” as an unsupported plan. Copy necessary nonsensitive context into the task or use a supported accessible source, then verify that path. This run creates no automation. [Scheduled tasks](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)

## Review and closure

ChatGPT should deliver the actual useful transformation and repair defects it can detect. A professional presentation requires communicative judgment and rehearsal/recipient fit where material; a rendered PDF is only evidence of rendering. A decision needs legitimate preferences and reliable evidence; a scoring table is not decision quality. A deployed intervention needs receiving readiness and use; deployment is not outcome.

At closure, the useful answer is: what is ready for which use, what was actually checked, what remains uncertain, which state changed, and who owns any real-world next step. A bounded task can close without outcome monitoring when monitoring has no useful role. A long-running initiative needs a named source/owner for later evidence when that evidence can change the decision.

No ordinary prompt needs to reproduce this playbook. The live cooperation carrier supplies standing expectations; selected Skills supply methods; sources supply domain/state; the conversation supplies shared context; an AI-compiled brief carries what cannot travel automatically. The unavoidable residual operations are choosing an available surface, providing inaccessible context, mechanical transfer where product support is missing, and genuine judgment/authority. Their content should already be prepared for you.
