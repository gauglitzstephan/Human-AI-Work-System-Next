## Update rule

Update after a material decision, correction, authoritative-state change, Work return, conflict discovery, or handoff—not after every message. Preserve history in the authoritative system or version control when it matters; do not keep contradictory current statements merely to retain chronology.


## Actual update and reconciliation path

Use an existing suitable current record instead of creating this source if it already serves the initiative. ChatGPT should prepare and, within legitimate scope and available tool capability, save the material working-state delta proactively. If only the Project UI supports the write, return a complete ready-to-save source or replacement and identify the one mechanical Human action. Do not report a prepared update as saved.

Before replacing a consequential source, compare its latest version with the version used for this work. Reconcile nonconflicting deltas; expose material conflicts and preserve necessary history. Record the current pointer, version/date, status and supersession relation. An external authoritative record remains authoritative; this source carries its pointer and qualified working interpretation, not a competing operational truth.

A correction or Work return updates only the earned state: working hypothesis, evidence, recommendation, accepted decision or authorized action as actually established. Persisting a draft is not acceptance. On continuation recover this state and rebind the controlling parent, not the last child task.
