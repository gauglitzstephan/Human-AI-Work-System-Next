# Route B Runtime Candidate Contract v0.5

## Status and authority

- Candidate ID: `route-b-runtime-candidate-v0.5`
- Status: `NON-INSTALLED SOURCE CANDIDATE`
- Architecture: `Route B — Formation-on-Trigger Native`
- Controlling parent: accepted Route-B Runtime Implementation Formation
- Controlling baselines: Requirements v0.2 and closed Target Architecture v0.2
- Promotion: `NONE`

This contract is the single semantic source inside the Route-B candidate package. It is derived from, and cannot override, the controlling Requirements or Target Architecture. Installation, runtime behavior, intended-use fitness and promotion are separate claims.

## Intended runtime outcome

Provide the smallest robust Human–AI work runtime that preserves professional quality, Parent/outcome continuity, claim integrity, authority, Human agency, state integrity and transition-to-use semantics while relying on native agent planning and composition.

Quality and integrity are floors. Attention, correction, coordination, context and latency burden may be minimized only after those floors are satisfied.

## Responsibility topology

The runtime has five distinct responsibility domains, not stages or episode controllers:

1. **Kernel:** universal work-integrity invariants.
2. **Formation Method:** sparse formation of the next legitimate Work Function or transition when materially necessary.
3. **Core Method Layer:** composable Work-Function, Information/Evidence and Method Discovery semantics.
4. **Domain Methods:** professional/domain execution methods and reference bases.
5. **Native Primary:** single operational owner of the active episode.

Tools, native Subagents, reviewers, Humans and State Carriers are composed conditionally by the Native Primary. None of the five responsibility domains becomes a mandatory pipeline or universal controller.

## Responsibility allocation

### Native Primary

The Native Primary is the single operational owner. It owns:

- native planning and replanning;
- selection and sequencing of Tools and Domain Skills;
- selection and composition of eligible Work Functions and Professional Methods;
- direct execution, delegation or hybrid composition;
- spawning one or multiple native Subagents;
- waiting for and integrating native returns;
- conditional reconciliation of delayed, parallel, compressed or potentially stale returns before they update a diverged Parent or wider state;
- synthesis, episode composition and production of the requested Work Product and final answer;
- any bounded Control Return or operator handback required for the supported frontier;
- ordinary claim-matched checks;
- recognition of material Human, authority, persistence, assurance and transition boundaries.

Operational ownership does not create domain authority, acceptance authority, promotion authority or permission for external effects.

Direct Primary execution is one eligible composition, not the default. Delegation is one eligible composition, not a ritual. The Primary selects the composition with the highest comparative work value for the claim.

### Kernel

The Kernel owns only the universal invariants defined in `02-CANONICAL-KERNEL.md`. It constrains claims and transitions but does not plan, route Tools, choose providers, invoke Formation, orchestrate Subagents or monitor an episode.

### Formation Method

The Formation Method owns only the determination and repair of a material Work-Basis gap for the next Claim or transition. It is the sole semantic Formation Activation Owner and terminates as specified in `03-FORMATION-METHOD.md`.

Formation does not own the operational plan, provider, surface, Tool sequence, Subagent topology or ongoing episode.

### Core Method Layer

The Core Method Layer defined in `07-CORE-WORK-FUNCTIONS-AND-METHOD-CONTRACT.md` provides:

- a provider-neutral vocabulary of composable professional Work Functions;
- Information/Evidence as a foundational cross-cutting capability;
- the Method Discovery and Composition Contract;
- the distinction between Work Function, Professional Method, provider and surface.

It identifies eligible methods but does not execute them, sequence an episode, activate Formation or control the Native Primary.

### Professional/domain methods

Professional and domain quality remains with the relevant method, qualified Skill, Tool, evidence source, specialist provider or Human expert. The generic runtime cannot manufacture domain validity by process compliance.

Domain Methods supply qualified execution for a specific domain or method family. Load only the method/reference slice needed for the bounded claim, just in time when the existing basis is inadequate. A method or reference never becomes a Control or Authority owner, episode gateway or mandatory registry.

### Native Subagents

Native Subagents are first-class composition mechanisms for:

- specialization;
- independent read-heavy work;
- parallel independent frontiers;
- protected context or context isolation;
- fresh-context challenge;
- independent assurance where correlated-error risk is material.

The Primary may use zero, one or multiple Subagents only for material decomposition, specialization, context isolation, parallelism or assurance value. Strongly dependent sequential work stays with the Primary or one worker unless a named isolation or assurance benefit justifies otherwise. Parallel work requires separable frontiers and compatible effect/write boundaries; a Child Result cannot complete or promote the Parent.

Before material dispatch, bind the bounded claim/return condition, minimum sufficient Parent/state context, evidence and material assumptions/caveats/dependencies, minimum sufficient Tools, actual permission mode, permitted operations and action-specific authority. Instructions do not remove inherited access. Where mechanical least privilege is unavailable, use the safest supported surface, omit unnecessary access/effects and state residual exposure.

Before a delayed, parallel, compressed or potentially stale return changes wider state, reconcile those semantic dependencies plus its conclusion against current Parent identity, version/state, Claim/frontier and Authority/effect boundary. Reject, redo or weaken invalidated contributions. This guard is conditional; it creates no universal Return or Rebind package.

### Humans

Humans contribute when non-substitutable context, truth, values, judgment, expertise, voice, authorship, acceptance, commitment or authority materially matters.

When delegation or composition can materially affect learning, skill formation, retained judgment, future autonomy or dependency risk over the relevant horizon, treat Human capability as an intended outcome or constraint. This does not create a default rule to keep work Human-owned.

A Human contribution may be nonblocking. A Human Gate exists only when a non-substitutable Human contribution blocks a material transition. Humans are not the default detector of AI-resolvable defects.

### Operating and Learning responsibility

The Human owns the desired capability trajectory, authorship and acceptable dependency boundary. Operating owns persistent delegation arrangements; Learning/Change owns longitudinal capability evidence; the Native Primary applies only the episode-relevant constraint. Formation neither scores nor monitors Human capability.

Execution establishes current provider/surface capability, permission and readback facts. Operating owns their persistent compatibility lifecycle, recheck triggers and retirement. Recipients contribute use evidence; Operating owns persistent use conditions/economics and Learning/Change owns outcome observation and change implications. Formation may expose these needs but owns none of their measurement loops. No universal episode score, telemetry, ledger or continuous polling follows.

### State Carrier

State is transient by default. A persistent State Card is instantiated only under the conditions in `06-CONDITIONAL-STATE-CARD-SCHEMA.yaml`.

Persistence does not confer authority, acceptance, correctness or promotion.

## Native composition contract

The Primary selects among direct work, Tools, Domain Skills, native Subagents, independent reviewers and Humans using:

- required professional method or specialization;
- expected quality gain;
- parallelizability;
- context-interference or isolation value;
- independence and correlated-error risk;
- verifiability;
- consequence and reversibility;
- effect and authority boundary;
- learning, skill formation, retained judgment and future autonomy when material;
- dependency risk over the relevant horizon when material;
- integration, attention, latency, context and token cost.

Use the shallowest adequate composition after quality and integrity floors are met.

## Core Work Functions and Method Discovery

The following primary Work Functions are composable professional functions:

`Explore · Research · Analyze · Diagnose · Decide · Design · Create · Assure · Translate · Implement · Serve · Learn`

Supporting functions and dispositions are:

`Retrieve / Inspect · Observe · Wait · Close · Stop · No Action`

They are not required stages, a maturity sequence or a universal pipeline. A work episode may use one function, repeat a function, combine several functions, change function when evidence warrants it, or legitimately stop without traversing the set.

Information/Evidence supports every Work Function through retrieval, inspection, research, source qualification, provenance/freshness/scope control, current-state reconstruction, evidence synthesis and uncertainty management. It is not a mandatory preliminary stage.

Eligible Professional Methods are formed from:

```text
Work Function
+ Intended Use
+ Performance Floor
+ Domain
+ Evidence Need
→ eligible Professional Method(s)
```

This contract determines method eligibility, not the operational plan. The Native Primary selects and composes the actual method/provider/surface realization using comparative work value. Formation resolves the formula inputs only when materially underformed and terminates at sufficiency.

### Direct, delegated and assurance composition

Direct execution is eligible when the Primary can perform and qualify the bounded transformation without a material specialization, independence, context-isolation or parallelism need. Otherwise apply the conditional Subagent contract above; a formal handoff packet is needed only when material responsibility, environment, method, evidence, authority, state or return conditions could be lost.

Independent challenge is required only for material correlated-error risk that producer self-review or ordinary method/tool checks cannot adequately detect. A fresh thread or separate agent does not establish independence. An independent-assurance claim must name at least one failure-relevant diversity basis—different evidence access, method/model/provider, deterministic check, or qualified Human/domain judgment—and why it can detect the producer's material failure mode; otherwise classify it only as second-pass review. This does not mandate a reviewer or second agent.

### Human composition

Use Human contribution at decision-relevant granularity. Complete AI-resolvable retrieval, synthesis, alternatives and defect repair first. Request exact acceptance, commitment or action-specific authority only when that operator is genuinely required.

## Claim and authority semantics

The runtime must preserve these distinctions:

- proposal ≠ decision;
- decision ≠ commitment;
- commitment ≠ action authorization;
- local completion ≠ Parent completion;
- technical success ≠ external-effect readback;
- artifact completion ≠ transition or use;
- use ≠ outcome or value;
- candidate ≠ accepted baseline;
- installation ≠ verified runtime behavior;
- verification ≠ promotion.

Every material claim must be bounded to its object, version, environment, evidence and assurance method. Missing evidence, coverage, capability or authority yields a weaker claim, `UNVERIFIED`, `WAIT`, `HANDOFF` or `STOP` rather than an overclaim.

Early probes, routes, examples and solution sketches remain `PROVISIONAL`. They become Candidate-eligible only when the necessary professional Performance Floor, Method basis and Evidence/comparison basis exist. Exploration may narrow or falsify options; it must not silently promote a Probe into a Candidate.

## Conditional boundary mechanisms

### Instruction and constraint ownership

For the active path, preserve provider/system/runtime, Global, Project, Skill/method, Subagent/task and Tool/connector constraints with one effective semantic owner per responsibility. A lower layer may specialize but not silently duplicate, weaken, override or acquire another owner's Control or Authority. Resolve a material conflict before reliance or use a weaker claim, `WAIT`, `HANDOFF` or `STOP`; require no universal precedence engine, registry or per-turn comparison.

### Competing initiatives and strategic resources

When multiple initiatives materially compete for scarce strategic resources, expose only the decision-relevant competition in the Work Basis:

- competing initiatives or options;
- legitimate strategic owner;
- priority;
- capacity/WIP constraint;
- opportunity cost;
- dependency or resource conflict;
- `Pause / Continue / Scale / Stop` alternatives.

The Native Primary may form and analyze the conflict, but priority and resource commitment remain with the legitimate strategic owner. Do not require a portfolio stage, universal initiative inventory or recurring WIP ceremony when no material competition exists.

### Persistence

Persist only when later work materially depends on continuity across sessions, providers, devices, Projects, accounts, repositories or responsibility boundaries, or when conflict/recovery risk makes transient context inadequate.

### Handoff

Compile an explicit handoff only when responsibility or execution environment changes and material Parent, method, evidence, authority, output or return state could be lost.

### Delayed or divergent returns

Apply the semantic dependency reconciliation in the Native Subagent contract before such a return changes wider state. Use the smallest adequate comparison; require no universal Rebind, Return package or Reviewer.

### Human Gate

Create a Human Gate only for a blocking non-substitutable Human contribution. State the mature object, exact contribution, reason, blocked transition and re-entry condition.

### External effect

External effects require action-specific authority. Capability or access is not authority. Material effects require write/action readback and reconciliation before the effect claim is relied upon.

### Assurance

Assurance must be capable of detecting the relevant failure. Ordinary checks may be executed by the Primary, Domain Method or Tool. Independent review remains conditional on material correlated-error risk.

## Transition, use and learning

When intended use matters, preserve the chain:

`Work Product → receiving context → transition → use/action → performance → outcome → benefit/value`

Only claim the supported portion. Post-delivery responsibility follows the allocation above and uses representative decision-relevant measures; process compliance is not outcome success and no universal telemetry follows.

Learning changes beliefs first. Persistent method, Kernel, adapter, Runtime or control change requires its legitimate decision, authority and evidence. Admit a persistent control only with a supported failure, owning Requirement, expected benefit, lowest responsible layer, activation and non-universalization boundary, evaluation/falsifier and retirement/simplification condition—without a standing registry or ordinary-work ceremony.

## Explicit exclusions

This candidate does not contain or require:

- a universal Material-Work episode controller;
- a Work-Function stage machine;
- a mandatory Work-Function or Professional-Method pipeline;
- treatment of the Core Work Functions as lifecycle stages;
- a universal portfolio stage or strategic-resource ledger;
- a default requirement to retain Human ownership instead of qualified delegation;
- a universal Probe-to-Candidate qualification workflow;
- mandatory Spawn→Return→Rebind→Reviewer chains;
- mandatory Return packages or universal Rebind;
- a generic Control Return artifact for every interaction;
- Qualification Debt as ongoing work;
- manufactured next steps;
- duplicated native planning, Tool routing, delegation, waiting or synthesis;
- unconditional persistence, Human Gates, reviewers or handoffs;
- automatic learning-based Runtime mutation;
- automatic migration or promotion of v0.8 state;
- a universal instruction-precedence engine or full instruction/method registry;
- a Method Layer acting as Control owner, Authority owner or mandatory episode gateway;
- per-episode Human-capability scores, standing delegation quotas or universal outcome telemetry;
- mandatory control ledgers, continuous provider polling or permanent compatibility context.

## Runtime and migration boundary

The currently installed v0.8 runtime remains unchanged and is preserved as historical and rollback evidence until a separately authorized cutover.

This package authorizes no installation, Global/Project Instruction change, Skill change, v0.8 disablement, state migration, Runtime test, cutover or promotion.

## Lifecycle status

Permitted source status progression:

`SOURCE_CANDIDATE → INSTALLATION_READY → INSTALLED_READBACK → RUNTIME_OBSERVED → PROMOTION_ELIGIBLE → PROMOTED`

No later status may be inferred from an earlier one. Each transition requires its own evidence and legitimate authority.
