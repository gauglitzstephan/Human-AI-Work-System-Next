## 1. Design object and claim

This design specifies the minimum downstream realization needed for professional work to remain coherent across Chat, Projects, Work, Codex, tools, Apps and selectively activated Skills without introducing a universal orchestration layer.

It binds:

- surface-independent Pre-Execution sufficiency;
- surface and provider selection as bounded implementation choices, not work-state transitions;
- recover-before-ask and proportional information supply;
- conditional Formation, method activation, Execution and re-entry;
- Human-facing Joint Intelligence and decision UX;
- provider/capability/access/Authority boundaries;
- source, installation, session load, behavior and outcome as separate claims;
- one byte-identical Global kernel reused by the System-Development Project carrier.

It does not prescribe a mandatory Chat→Work handoff, automatic transcript/state migration, universal dashboard, extra Runtime controller, standing Human gate or new Skill.

## 3. Realization invariants

1. **Pre-Execution is surface-independent.** Any material Execution requires a QWS sufficient to prevent reinterpretation of object/outcome/frontier, use/floor/ambition, basis/method/effective-provider fit, scope/preservation/latitude, Human reservation/Commitment/Authority and Assurance/re-entry.
2. **Surface movement is not readiness.** Chat→Work, Project→Codex, tool invocation, Skill activation or provider return neither forms the QWS nor authorizes Execution.
3. **Recover before asking.** Accessible Conversation, Project and claim-fit sources/providers are recovered before Human questions; inaccessible or genuinely non-substitutable input returns to the Human.
4. **Formation is conditional.** Only a specification-defining gap activates `work-formation`; ordinary evidence, production, continuation or provider return does not.
5. **Methods are not stages.** Skills activate only on their real triggers. Direct read/query/measurement and narrower qualified methods remain available.
6. **Execution is completion-seeking within latitude.** It may recover/acquire, choose providers, iterate, repair and assure, but may not redefine outcome, scope, use, performance, Candidate, Human reservation or Authority.
7. **Return is evidence- or judgment-dependent.** Slice/return occurs only when early evidence or Human judgment can change Candidate, route, taste/quality, method/craft or scale.
8. **Authority and claims remain typed.** Capability, access, effective capability, permission/Authority, accountability, Acceptance, installation, load, behavior, use, outcome and value are not collapsed.

## 4. Surface and provider allocation

| Surface/provider | Default contribution | Boundary |
|---|---|---|
| Chat / Joint Intelligence | Interpret, recover, frame/reframe, challenge, explore, calibrate Human judgment/taste/ambition/learning, deliberate and record actual decisions | Default Human-facing carrier; not a universal planning pipeline or mandatory gate |
| Work | Substantial bounded Execution, tool use and artifact production when effective and available | Work entry does not prove QWS, Authority, professional basis or completion |
| Project | Shared instructions, files and connected sources for related Chat/Work episodes | Project membership does not prove automatic transcript/state migration or session-effective application |
| Codex / tools / Apps | Bounded production, retrieval, transformation or external effect | Provider result is a contribution, not Parent ownership, Acceptance, Promotion or wider completion |
| Skills | Trigger-specific professional method | Skill presence, naming, READY or result is not activation, integrated QWS or Authorization |
| Human | Non-substitutable context, judgment, values, taste, expertise, authorship, learning, Acceptance, Commitment and Authority | Human is not routine recovery/QA fallback for AI-resolvable work |

Surface selection uses bound work state, effective capability, verifiability, consequence, context isolation, cost and Authority. A Human may reserve a surface. If the reserved path cannot meet the intended-use floor, the conflict is made legible and the work is narrowed, rerouted, handed off, waited or stopped.

## 5. Formation, method and failure routing

| Condition | Route | Negative guard / failure disposition |
|---|---|---|
| Materially open frame or route | `adaptive-exploration` | Not for a mere specification, evidence or production gap |
| Specification-defining gap | `work-formation` | Never carrier-emulate; failure → weaker claim, narrow, wait, handoff, stop or no action |
| Material bounded evidence gap | `research-evidence` on real trigger | Adequate evidence or a direct read/query/measurement stays native/narrower; recurring information belongs to its legitimate owner |
| Bounded material choice | `decision-analysis` | Not a substitute for open exploration, missing specification or missing evidence |
| Existing product fitness/use claim | `evaluate-work-product` | Not a creation, rewrite or generic research method |
| System/runtime/repository work | `system-development` | Not a universal domain-delivery method |
| Sufficient ordinary work | Native/qualified Execution | No Skill theater or manufactured frontier |

Consequential Safety, Security, Privacy, Rights/Fairness, legal/professional or irreversible/hard-to-recover effects require proportionate Authority, protection, justified exposure/privilege, containment and Recovery. Strategic ranking requires purpose/priority, dependencies, capacity/WIP, Opportunity Cost and Stop/Pause/Scale; absent material basis, qualify/form or make a narrower recommendation rather than silently ranking.

## 6. Human interaction and return

When Human judgment is material, the smallest concrete decision object is preferred:

- an artifact, prototype or slice; or
- two to three mechanism-distinct options with consequences and a supported default.

This supports judgment without turning review into AI QA. Changed Human judgment/value/taste routes to Chat; new material reality routes to recovery/acquisition and requalification of only dependent QWS state; production defects stay in Execution; specification defects return to Formation.

## 7. Carrier composition

The Global carrier is one complete compiled kernel. The System-Development Project carrier begins with that kernel byte-for-byte and adds only a Project overlay for:

- authoritative repository/Project/domain recovery;
- the source/method precedence boundary;
- native surface/provider selection for system work;
- repository write/PR/merge Authority and readback;
- source Promotion versus UI/Skill installation, session load, behavior and outcome;
- concise Human-boundary return.

The Project carrier is self-contained; correctness does not depend on undocumented automatic Global+Project concatenation.

## 8. Deployment, readback and reliance

Repository Promotion establishes only current repository source after authorized merge and authoritative `main` readback. It does not update ChatGPT Global or Project instruction fields, install Skills, prove session-effective load or establish behavior.

Any later deployment is a separate authorized transition:

1. bind account/workspace/Project and target carrier fields;
2. install the exact accepted payloads;
3. read back exact Unicode/count/hash;
4. close/reopen or start a fresh session when the reliance claim requires load evidence;
5. run only claim-matched behavioral tests;
6. preserve installed identity, activation, behavioral conformance, professional fitness, Performance, outcome and value as separate claims.
