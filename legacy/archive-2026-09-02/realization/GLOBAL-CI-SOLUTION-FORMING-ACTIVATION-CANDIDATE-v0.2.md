## Ownership correction from v0.1

`Solution Formation` is **not** treated as a new lifecycle stage, architecture object, agent, store or standalone method owner.

Existing owners already provide most of the function:
- Qualification / DWM: current-system baseline and observed-failure recovery before redesign;
- Work Lifecycle: `Reference + Reuse / Solution Intelligence` and `preserve / repair / retire / replace` design decisions;
- Pattern/Reuse + Orchestration: `REUSE / ADAPT / COMBINE / REJECT / DESIGN NEW`, route challenge, simpler/no-action and transfer appraisal;
- Semantic Compiler: minimum next legitimate work;
- B.6 DESIGN/COMPOSE: sufficient design/capability composition;
- Execution + Realization: instantiate, transition, use and validate.

The remaining Runtime gap is **activation salience**: make those existing functions compose early enough that solution-building does not default into decomposition/meta-artifact production before the solution route is formed.

## Intended delta from the incumbent

The new Runtime hook does not add a new process owner. It increases activation salience for an already distributed solution-forming behavior:

```text
existing-system review / qualification
+ Solution Intelligence / reuse
+ open-route challenge when needed
+ decision / uncertainty / commitment
+ sufficient design
→ instantiate / configure / build
→ readback / representative use
```

In particular, decomposition is downstream of solution-route formation for solution-building work unless decomposition itself is required to discriminate the route.
