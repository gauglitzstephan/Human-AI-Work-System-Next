## 0. Decision in one page

The Human–AI Work System is **natively executable in substantial parts**, but no evidenced Native mechanism enforces its full QWS/state/routing contract end-to-end and across surfaces.

ChatGPT Native supplies real execution capacity: dialogue and reasoning, Work, Projects, files and artifact production, search and browser access, shell/repository work, Skills, apps/connectors, subagents, long-running work, scheduled tasks, and permission/sandbox mechanisms. These capabilities are surface-, account-, workspace- and access-conditional.

The system-specific control semantics—Work Object, Parent/Frontier, Active Work State, QWS, conditional Specification Formation, Adaptive Work Selection, professional-method activation, claim calibration, re-entry and most status distinctions—are primarily **Instruction Semantics executed probabilistically by the model**. ChatGPT has no evidenced native QWS object, typed Work-State store, deterministic router, method-activation gate, promotion operator or universal cross-surface transaction/readback contract.

Hard control exists only where a real mechanism owns it: Native sandbox/network/action allowlists; configured Codex Rules or synchronous blocking Hooks on eligible paths; external connector/OAuth/source-system rights, repository protection and server/tool authorization; or Human/external professional Authority. Approval policy and app confirmations are interruption/review controls, not by themselves access or least-privilege enforcement. Background Hooks and ordinary instructions do not provide universal blocking. Instructions can guide behavior inside those boundaries; they cannot create access or Authority.

Therefore the strongest supported claim is:

> This map is a point-in-time, surface- and account-conditional mapping of every material system function to documented ChatGPT-Native capabilities, dated episode-specific effective evidence, Instruction Semantics, bounded providers, Human/external owners and explicit claim limits.

It does **not** establish that the system is installed, active, behaviorally conformant, professionally fit, outcome-effective or generally operational.

## 2. Classification scheme

Each function may carry more than one class because an executable capability can still depend on Instruction Semantics and a separate enforcement owner.

| Class | Meaning |
|---|---|
| `NHC` — NATIVE_HARD_CONTROL | A ChatGPT/Codex product boundary can enforce the condition, such as sandbox/network scope, action allowlists, configured Rules or synchronous blocking Hooks. It does not supply subject-matter Authority. |
| `EHC` — EXTERNAL_HARD_CONTROL | A non-ChatGPT owner enforces the condition, such as OAuth/source-system rights, server authorization, repository protection or an external tool schema. |
| `RC` — REVIEW_CONTROL | Approval policy, app confirmation or reviewer routing can pause, refuse or route an action. It is not by itself an access boundary, professional Authority or deterministic least-privilege mechanism. |
| `EAC` — EXECUTABLE_AGENTIC_CAPABILITY | ChatGPT can perform the transformation through reasoning, generation, tools or delegated agents. Correct invocation and result quality are not guaranteed. |
| `IS` — INSTRUCTION_SEMANTIC | Global/Project instructions, `AGENTS.md`, prompts or Skill text guide model behavior. This is not a deterministic gate. |
| `DB` — DELEGATED_AND_BOUND | A Skill, connector, professional method, tool or subagent performs a bounded contribution that Native must integrate. |
| `SAC` — SURFACE_ACCOUNT_CONDITIONAL | Availability or semantics vary by plan, workspace, rollout, platform, local/cloud mode, connection or permission. |
| `HEO` — HUMAN_OR_EXTERNAL_OWNER | Legitimate Authority or a durable external system owns the decision, state or action. |
| `U` — UNVERIFIED | Plausible or documented, but effective access/activation/behavior for the claimed path is not established. |
| `X` — UNSUPPORTED | No qualifying native mechanism supports the stronger claim. |

An `IS` function is represented, not implemented in the hard-control sense. An `EAC` function is executable, not thereby correct, authorized, persistent or accepted.

## 10. Claim-matched validation before stronger reliance

Do not create a ceremonial full-system test cycle. Select only tests that can change a real reliance decision.

1. **Cue-free activation:** use a material trigger without words such as “Skill”, “Formation” or “parallel”; observe actual behavior, not prose about behavior.
2. **Explicit versus implicit Skill:** test separately; one does not prove the other.
3. **Surface-paired behavior:** run the same relevant case on each claimed path; mark others `OUT_OF_RUNTIME_CLAIM`.
4. **Permission/Authority collision:** use a harmless simulation, dry run, read-only probe or required refusal to test a technically possible but unauthorized action; pair it with an authorized but technically unavailable action. Never create a consequential unauthorized effect for validation.
5. **State divergence:** present stale chat/Memory context against a newer authoritative source and require correct reconciliation.
6. **Handoff/return/readback:** exercise the full provider or cross-surface loop and inspect Parent integration.
7. **Professional-method challenge:** compare plausible generic output with a method-qualified intended-use product.
8. **Paired proportionality:** direct-execute a well-bound small task; do not prematurely execute a materially underformed task.
9. **Human-burden check:** Human must not be the routine detector of AI-resolvable recovery or QA defects.
10. **Correlated-error check:** count a second agent as assurance only if its method/evidence can detect a different failure.

Reuse F01–F20/RC01–RC10 where the claim matches. Do not report SR01–SR07 as evidence until executed.

- Deterministic QWS/Formation/Adaptive Work Selection or Skill activation.
- A universal ChatGPT state store, cross-surface handoff contract or two-way repository/runtime synchronization.
- Current QOC installed-carrier identity or behavioral conformance.
- Generic professional-quality, independent assurance, outcome or value from product capability alone.
- Universal external-write confirmation, rollback or post-write readback.
- Current QOC installation/load/application merely because the product contract says Project Instructions override Global Custom Instructions.

### Reliance boundary

The map and repository representation are coherent at repository-source level. No product unknown changes this representation. Remaining unknowns are reliance-specific evidence units, not evidence of installation, operational reliability or outcome. On a branch/PR, Human Acceptance of the exact final head and separate merge authorization remain outstanding; on authoritative `main`, current status requires post-merge readback.
