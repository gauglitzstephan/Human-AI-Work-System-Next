## 3. Activation-topology repair

### Prior v0.2 risk

Global v0.2 represented:

```text
ORCHESTRATE
FORMATION
METHOD+TEAM
STATE+AUTHORITY
PROMOTION
EXECUTE+INTEGRATE
REFINE+ASSURE
GATES+REALIZATION

```

as nine peer top-level blocks. Semantics were broad, but the layout could make conditional controls appear globally active and process-like.

### v0.3 topology

v0.3 compiles the same control space as:

```text
ALWAYS
= permanent integrity/authority/state invariants

CONTROL
= Work Controller / Semantic Compiler
  binds parent/state/gate
  selects minimum valid frontier

CONDITIONAL CAPABILITIES
= FORM+DECIDE
= REALIZE / Professional Method / Teaming
= CLAIM+STATE controls: Assurance / Promotion / Human Gate
= TRANSITION+LEARN / Closure
```

The numbered blocks are not mandatory stages. Their activation clauses are explicit:

- Formation: only while problem/route/commitment is open;
- Method/capability: only as needed;
- Assurance: for material claims;
- Promotion: only on status/control change;
- Human Gate: only if Human contribution blocks a transition;
- Transition/learning: only when success depends on use/new evidence.

**Activation-topology verdict: PASS.**
