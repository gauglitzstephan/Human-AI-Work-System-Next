# Activation Coverage Check — 2026-09-02

**Status:** REBASELINE EVIDENCE / NO NEW RUNTIME

## Question

Does the minimal substantial-work invariant need another custom mechanism?

Candidate shorthand:

**Recover / Acquire / Benchmark → Requalify → Produce → Evaluate**

This is shorthand for information and quality obligations, not a mandatory lifecycle or state machine.

## Finding

**No additional Global-CI rule or custom runtime layer is currently justified.**

The semantic coverage already exists across the current Global CI plus native ChatGPT/product capabilities:

1. **Recover + Requalify** — the current CI explicitly requires recovery and requalification of accessible context, prior work, methods, references and capabilities before substantial work when they could materially affect the result.
2. **Acquire fresh reality** — the current CI already requires verification or exposure of gaps when current/external facts could change the answer; native Web, Apps, Files/Drive, Deep Research and other connected capabilities supply external/current evidence.
3. **Benchmark / professional reference calibration** — the current CI already requires seeking relevant exemplars, counterexamples, anti-references, standards or strong work when they materially improve judgment.
4. **Professional method/provider use** — native/plugin/skill capabilities can supply repeatable or domain-specific workflow methods; repository-local Skills are not the provider universe.
5. **Produce toward intended use** — the CI already requires professional-level work, intended-outcome completeness and recipient/use relevance; ChatGPT Work is intended for substantial clearly defined multi-step work producing reviewable deliverables.
6. **Evaluate** — the CI already requires checking substantial work against intended outcome and material missing dimensions/failure modes; proportional claim-matched assurance and `evaluate-work-product` remain candidate mechanisms where native/domain evaluation is insufficient.

## Native-product evidence

Current OpenAI product documentation establishes that:

- Projects preserve and prioritize relevant project chats/files/context for ongoing work.
- Plugins are the primary discovery layer for workflow capabilities and may package Skills and Apps.
- Skills are reusable workflows that ChatGPT can automatically use when helpful.
- ChatGPT Work is designed for substantial, clearly defined, multi-step knowledge work using context/tools to produce a finished reviewable deliverable.

These capabilities support the invariant but do **not** establish a documented guarantee that every substantial task will always execute the full shorthand sequence correctly.

## Rebaseline implication

The remaining problem is therefore **activation/execution reliability**, not missing conceptual coverage.

Do not respond to a future failure by automatically adding another lifecycle, router, state object, CI sentence or Skill. First classify the failure against an already-existing invariant:

- invariant absent;
- invariant present but relevant context/capability unavailable;
- invariant present but not activated/applied;
- provider/method inadequate;
- evaluation failed to detect the defect.

Only the first case is evidence for adding new semantics.

## Relation to genuine-use evidence

The NYBA application run is positive-but-limited evidence:

- relevant application state and current Candidate/Direction/Writing/Visual carriers were recovered;
- a current Master CV carrier was found and reused instead of rebuilding from scratch;
- external opportunity reality was freshly checked;
- claim boundaries were preserved;
- output quality improved materially versus the Sika failure.

Remaining defects in the recovered carrier (for example date/hierarchy treatment) show why recovery must not imply automatic acceptance: qualified reuse remains necessary.

## Decision

**NO CI PATCH. NO NEW RUNTIME. NO NEW GENERIC SKILL.**

Continue the rebaseline using the existing semantic invariants and ordinary real work. Treat failures as activation/provider/evaluation evidence unless an actually missing invariant is demonstrated.
