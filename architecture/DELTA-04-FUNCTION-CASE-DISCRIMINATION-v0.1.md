## 1. Executive discrimination

The historical Semantic Compiler bundles two different classes of function:

```text
CLASS A — already-qualified Work Architecture / routing semantics
- preserve valid work
- reopen only affected dependencies
- use current authoritative state
- select method / capability / Human Gate proportionately
- decompose conditionally
- qualify the exact claim
- stop at the legitimate boundary

CLASS B — potentially incremental metareasoning / decision policies
- explicit next-state target as a control variable
- explicit minimum-next-frontier projection
- Information Value hardening
- Prospective Robustness / signposts
- Commitment Design / staged action
```

The first class does **not** justify a separate adaptive controller. Those mechanisms already belong to qualified Work Architecture or minimal routing.

The second class merits differential testing, but current external references support them primarily as **conditional metareasoning / decision policies**, not as evidence for one universal central Work Engine.

### Leading architectural hypothesis

> **Do not promote the full Semantic Compiler as a new architectural object. Test a thin conditional Adaptive Work-Control metapolicy inside Work Architecture.**

The metapolicy may later retain the `Semantic Compiler` label as an explanatory/compilation metaphor, but the label does not earn additional responsibility.

## E4 — v0.3.4 whole-task representative results

Pre-explicit-Compiler runtime already showed:
- direct simple-task behavior;
- current-reference route challenge and high-value uncertainty identification in an Etsy decision;
- strong actual-state-first repair in Bewerbung_2026;
- professional artifact generation with calibrated readiness boundary.

**Implication:** much of the desired behavior existed before the explicit B.6 Semantic Compiler. B has a high incremental burden of proof.

## E5 — Pre-Commitment Gate experiment

An explicit general pre-commitment control failed the 10-day / €5k case:
- still anchored on a productized consulting route;
- generated unsupported funnel/activity targets;
- failed to acquire the few context variables able to change the route.

The experiment was halted because additional runs had low information value.

**Implication:** explicit central gating is not sufficient and can be the wrong abstraction. Δ4 should not revive gate/trigger micro-testing.

## E6 — B.6 / uncertainty-aware integration

Static integration established that Information Value, Prospective Robustness and Commitment Design can be placed coherently as conditional compiler policies without adding layers.

**Evidence boundary:** architecture coherence / coverage only. Behavioral incremental value remained explicitly pending.

## E7 — Runtime salience history

v0.6.1→v0.6.2 showed a finite semantic-salience budget: detailed decision-edge logic competed for runtime space with historically necessary Work Product, mechanism-breadth and recipient-maturity cues.

**Implication:** B has a real opportunity cost. A new global metapolicy must earn scarce activation salience rather than merely be conceptually valid.

# 4. External reference discrimination

The external reference question is **not whether information value, robustness or flexibility are valid ideas**. The relevant question is whether the research supports bundling them into a universal Human–AI work controller.

## 4.1 Rational metareasoning / Value of Computation

Callaway et al., *Learning to select computations* (2017) model intelligent control as a **metalevel policy for selecting computations** under limited computational resources, including when to stop computation, how to allocate computation between options and planning.

Source: https://arxiv.org/abs/1711.06892

De Sabbata, Sumers & Griffiths, *Rational Metareasoning for Large Language Models* (2024), apply Value-of-Computation ideas to LLM reasoning and report lower inference use while maintaining task performance in their tested settings.

Source: https://arxiv.org/abs/2410.05563

**Transfer implication:** a thin metapolicy governing whether more cognition/information is worth performing is reference-supported in principle. This supports an Information-Value / stopping control **function**. It does not establish the Semantic Compiler's full bundle or system-wide architectural centrality.

## 4.2 Costly learning / optimal stopping

Harrison & Sunar (2015), *Investment Timing with Incomplete Information and Multiple Means of Learning*, explicitly model costly learning modes plus when to stop learning and invest/abandon.

DOI: https://doi.org/10.1287/opre.2015.1344

**Transfer implication:** learnability, information quality, information cost and stopping belong together in decision-sensitive work. This is stronger than generic `unknown could matter → research`.

## 4.3 Robust Decision Making under deep uncertainty

RAND's Robust Decision Making tradition evaluates strategies across many plausible futures when a single probabilistic forecast is not a sound basis, identifies vulnerabilities and seeks robust/adaptive strategies rather than one optimum under one assumed future.

Example source: https://www.rand.org/content/dam/rand/pubs/research_reports/RR2900/RR2931/RAND_RR2931.pdf

**Transfer implication:** Prospective Robustness is a legitimate conditional decision method where deep uncertainty is material. Nothing here implies that every Work Episode needs future-scenario logic or that RDM belongs as a permanent central controller function.

## 4.4 Real options / staged commitment

Harrison & Sunar (2015) connect costly learning to investment timing. Childs & Triantis (1999) analyze dynamic R&D investment where learning, speed and flexibility interact. Chavda (2023) shows that retaining termination flexibility is not universally beneficial: its value depends on early learning and resource conditions.

Sources:
- https://doi.org/10.1287/opre.2015.1344
- https://doi.org/10.1287/mnsc.45.10.1359
- https://doi.org/10.1287/stsc.2021.0095

**Transfer implication:** staged/reversible commitment is condition-dependent, and the correct metapolicy must include the anti-optionality case: **commit when delay/flexibility no longer earns its cost**.

# 5. Architectural placement discrimination

The references plus predecessor evidence support the following type correction:

```text
WORK ARCHITECTURE
owns:
  Work Object / Work Product / State / Work Units / composition /
  authority / assurance / realization / local recovery

CONDITIONAL ADAPTIVE WORK-CONTROL METAPOLICY
may govern, when decision-relevant uncertainty/commitment is material:
  what is the next legitimate decision/state?
  should we learn more?
  should we robustify instead of predict?
  how far should we commit now?
  when should we stop further cognition/flexibility?

PROFESSIONAL / DECISION METHODS
own detailed execution:
  quantitative VoI
  forecasting
  scenario / RDM analysis
  real-options valuation
  experiments / pilots
  domain-specific decision analysis
```

This is preferable to:

```text
Semantic Compiler
= owner of every adaptive Work Architecture function
```

because most of those functions already have qualified owners.

# 6. Surviving Δ4 candidate

## Thin Adaptive Work-Control Metapolicy — candidate v0.1

Activate only when **additional information, future uncertainty or commitment structure can materially alter the next decision/state**.

```text
1. NEXT STATE
   What exact decision / claim / state transition is legitimate next?

2. LEARN?
   Is there an unresolved variable that can materially change the route?
   Is it sufficiently learnable now?
   Is expected decision improvement worth acquisition + delay + coordination cost?

   yes → acquire the smallest decision-changing evidence
   no  → do not research merely because uncertainty exists

3. ROBUSTIFY?
   If material uncertainty cannot/should not be resolved now:
   stress-test only decision-relevant plausible states;
   expose vulnerabilities/breakpoints;
   retain useful signposts/adaptation triggers.

4. COMMIT?
   Compare only when material:
   WAIT / PILOT-TEST / STAGE / REVERSIBLE ACTION /
   INFORMATION-GENERATING ACTION / FULL COMMITMENT.

   Preserve flexibility only while expected learning/option value exceeds
   delay + coordination + lost-opportunity + flexibility cost.

5. STOP / EMIT
   Stop additional cognition once it cannot change the decision enough to
   justify its cost. Return the smallest next decision/action frontier.
```

### Deliberately absent

The thin candidate does **not** own or duplicate:
- reality retrieval;
- Work Object reconstruction;
- Work Unit decomposition;
- actor allocation;
- Human Gate semantics;
- generic preservation/local reopening;
- professional method selection;
- assurance/readiness;
- realization.

Those remain in qualified Work Architecture / other architecture responsibilities.

> **Does adding the thin `NEXT STATE → LEARN / ROBUSTIFY / COMMIT → STOP` metapolicy to the same qualified Work Architecture improve whole-task decisions under uncertainty/commitment enough to justify its activation and semantic cost?**
