# Δ4 — Adaptive Work-Control Differential Review v0.1

**Status:** STAGE 0/1 — DIFFERENTIAL FRAMING + PRIOR-EVIDENCE RECOVERY  
**Date:** 2026-08-19  
**Parent baseline:** Bootstrap / Differential Reconciliation v0.1 (`main`)  
**Question:** Does an explicit Semantic Compiler / adaptive Work-Control policy add unique behavioral value beyond already-qualified Work Architecture and a minimal PAOS-style routing model, after semantic, cognitive, runtime and maintenance cost are included?

This is **not** a proposal for a peer `Work Engine` layer.

---

# 1. Decision to make

Compare three existing design families rather than inventing a fourth from scratch:

```text
A — QUALIFIED WORK ARCHITECTURE
    accepted Work Architecture semantics
    without a separately named adaptive controller

B — WORK ARCHITECTURE + SEMANTIC COMPILER
    same broad work semantics
    plus explicit next-state / minimum-frontier control policy

C — PAOS MINIMAL CONDITIONAL ROUTING
    small operating kernel / direct path
    plus conditional context, method, tool and acceptance routing
```

A new `Work Engine` construct is admissible only if none of A/B/C can represent a material required function without loss.

---

# 2. Qualified prior A — Work Architecture

Primary source: `AI-native-Operating-Model/docs/03-work-architecture/README.md`.

Accepted Work Architecture already contains:

- outcome/Work Object formation rather than literal prompt following;
- authoritative reality and professional-reference grounding;
- method/reasoning-mode selection;
- investigation of **decision-flipping unknowns**, not exhaustive uncertainty;
- simpler/no-action alternatives where credible;
- Work Graph + conditional Work Units;
- allocation among Human / AI / Human+AI / tool / workflow / existing process;
- execution, dependency resolution, integration and refinement;
- local reopening after changed evidence;
- state / authority distinctions;
- claim-matched assurance;
- Work Product → transition/use → outcome/value realization;
- closure at sufficient evidence / net value;
- evidence-qualified Knowledge Capital promotion.

Important implication:

> **A is already adaptive.**

Δ4 cannot justify B merely by showing that B can orient, decompose, select methods, ask only when necessary, preserve work, handle uncertainty or stop. Much of that function is already present in A.

# 3. Candidate B — Semantic Compiler / adaptive Work-Control

Primary source: `Human-AI-Work-System/core/orchestration-model.md` v0.5.

The Semantic Compiler is explicitly defined there as an **orchestration policy**, not a separate agent/product/lifecycle/module:

```text
current authoritative state
+ contemplated claim / state transition
+ requirements / Performance Model
+ blockers / dependencies
+ authority
+ available/effective capabilities
+ consequence / reversibility
+ relevant uncertainty / horizon where material
        ↓
Semantic Compiler
        ↓
minimum sufficient admissible work frontier
```

Candidate incremental mechanisms include:

1. **Next legitimate state as explicit control variable**
   - choose work relative to a contemplated claim/state transition rather than only the overall Work Object/outcome.

2. **Preservation / local-reopen policy**
   - identify already-qualified state;
   - reopen only conditions/dependencies that materially block the next transition.

3. **Minimum admissible frontier emission**
   - explicitly output only the Work Units/actions/evidence/assurance/Human Gate needed for the next state.

4. **Information Value policy**
   - acquire additional information only when it can change the next action/claim and its expected decision value exceeds acquisition/delay/coordination cost.

5. **Prospective Robustness policy**
   - when future/external change can materially flip the route and is not worth/resolvable to forecast, stress-test decision-relevant plausible states and preserve signposts/adaptation triggers.

6. **Commitment Design policy**
   - compare wait/pilot/staged/reversible/information-generating/full commitment rather than treating decisions as immediate binary choices.

These functions must be tested for **incremental** value over A, not for standalone plausibility.

# 4. Counter-design C — PAOS minimal conditional routing

Primary source: `PAOS/OPERATING_LOOP.md` plus PAOS Minimum Kernel.

PAOS deliberately keeps ordinary work small:

```text
Orient
→ Explore/frame when needed
→ Assemble relevant context/capability
→ Work
→ Evaluate / Human acceptance where material
→ Close / continue / repair / local learning
```

For clear low-risk work:

```text
Input → useful output
```

For material work it already requires:

- actual purpose/output;
- relevant context/domain evidence;
- smallest adequate method/skill/workflow/tool;
- execution inside authorized boundary;
- technical vs substantive vs Human acceptance distinction;
- local learning only when material.

PAOS therefore represents the strongest current **minimum-complexity rival**:

> perhaps capable model reasoning + good Work Architecture semantics + a few strong routing/integrity boundaries is enough, and an explicit next-state controller adds more semantic burden than behavioral value.

# 6. Existing behavioral evidence — useful but not causal for B

The `Human-AI-Work-System/evaluation/b6-system-snapshot-2026-08-19.md` records positive real-use signals under the broader B.6-style system, including:

- authoritative-state recovery changing the work frontier;
- reuse/preservation instead of unnecessary regeneration;
- stopping broad research after decision-flipping unknowns were localized;
- fewer unnecessary modules/trackers/graphs;
- local repair rather than global restart;
- clearer Human-only gates;
- more precise next-action frontiers;
- stronger willingness to retain `UNVERIFIED` rather than manufacture closure.

It also records positive qualitative Human observation of improved response quality/performance.

However:

```text
B.6 + Core + runtime + state/reality semantics + Work Graph + assurance + realization + Semantic Compiler
→ observed improvement
```

cannot establish:

```text
Semantic Compiler specifically
→ caused the improvement
```

### Evidence disposition

**Support for system direction:** meaningful.  
**Evidence for compiler-specific incremental value:** weak/confounded.  
**Δ4 architectural promotion:** not yet justified.

# 7. The real Δ4 hypotheses

## H0 — No explicit adaptive controller needed

A + capable model reasoning + proportional runtime routing is sufficient.

Semantic Compiler is mostly a useful explanatory compression of already-accepted Work Architecture semantics.

### Prediction
Removing the explicit compiler while preserving Work Architecture causes little/no degradation on representative work.

---

## H1 — Thin adaptive control policy adds value

A small explicit control policy improves **work selection**, particularly:

- preserving already-qualified state;
- localizing the exact next legitimate claim/state;
- suppressing unnecessary work;
- choosing whether additional information is worth acquiring;
- deciding continue/stop/reopen;
- preventing stronger-than-supported completion.

But detailed VoI/robustness/commitment methods remain conditional capabilities/reference methods rather than permanent controller semantics.

### Prediction
A thin policy materially reduces overwork, unnecessary reopening, false completion or Human coordination burden without harming simple-task flow.

---

## H2 — Full Semantic Compiler policy is justified

The explicit combination of next-state control + Information Value + Prospective Robustness + Commitment Design is broadly necessary inside Work Architecture.

### Prediction
The full policy produces reproducible gains on both ordinary and uncertainty-sensitive work that cannot be matched by A or C with lower semantic burden.

---

## H3 — Routing-profile approach dominates

PAOS-style routing and domain/capability methods outperform a generalized controller because work-selection intelligence is better left to the capable model plus local method/context.

### Prediction
C matches or beats B on professional quality and failure prevention while using less context, fewer explicit states and less maintenance.

# 8. Candidate evaluation dimensions

Δ4 must compare **whole-work behavior**, not framework conformity.

Minimum dimensions:

- professional/intended-use quality;
- critical error / false completion;
- preservation of valid existing work;
- unnecessary work / unnecessary research;
- Human questions / Human correction burden;
- correct stop / continue / reopen behavior;
- state-recovery correctness;
- decision quality under material uncertainty;
- commitment/reversibility quality where relevant;
- simple-task latency/verbosity/process inflation;
- turns/tokens/tool calls where measurable;
- semantic/runtime burden of the treatment itself.

Non-compensatory failures should include at least:

- destroys/rebuilds valid authoritative work without reason;
- claims stronger readiness than evidence supports;
- opens extensive research with no plausible decision value;
- fails a material authority/action boundary;
- turns a simple task into process ceremony;
- misses a future/commitment issue that materially flips a consequential decision when the treatment claims to cover it.

---

# 9. Candidate test families

Do not build a large synthetic suite before checking existing evidence.

Use a small discriminating set, preferentially recovered from real work:

1. **simple direct work** — B must disappear;
2. **repair existing artifact/state** — preservation/local reopen;
3. **open professional analysis** — work-selection / stopping;
4. **research question with low-value unknowns** — Information Value;
5. **decision under learnable uncertainty** — acquire evidence vs act;
6. **decision under deep/future uncertainty** — robustness/signposts;
7. **reversible vs irreversible commitment** — staging/option value;
8. **persistent state mismatch** — exact next-state frontier;
9. **material Human authority boundary** — Human Gate only when blocking;
10. **multi-step professional artifact** — avoid premature downstream work.

The first pass should use existing real cases where possible before generating new fixtures.

---

# 10. Promotion rule

An explicit adaptive Work-Control mechanism earns architectural status only if:

```text
unique discriminating function
AND
reproducible behavioral gain
AND
benefit exceeds semantic/context/coordination cost
AND
cannot be represented more simply as:
  - existing Work Architecture semantics,
  - a conditional capability/method,
  - a runtime routing rule,
  - or model-local reasoning.
```

Possible dispositions:

```text
REJECT explicit controller
RETAIN AS EXPLANATORY MODEL ONLY
RETAIN THIN WORK-CONTROL POLICY
RETAIN CONDITIONAL METHOD/CAPABILITY
RETAIN FULL SEMANTIC COMPILER
REOPEN broader Work Architecture
```

No `Work Engine` naming/promotion before this decision.
