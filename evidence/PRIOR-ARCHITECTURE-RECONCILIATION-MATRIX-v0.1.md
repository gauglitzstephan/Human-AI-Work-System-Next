# 2. Qualified Prior A — AI-native Operating Model v0.2

## Prior claim/status

Accepted foundation architecture after external grounding and seven-scenario pressure/falsification review.

Accepted system shape:

```text
Strategic Architecture
Operating Architecture
Work Architecture
Execution Architecture
Learning Architecture
```

Cross-cutting:

```text
Reality & Provenance
Authority / Governance / Security
Assurance & Risk
Performance / Economics / Value
Knowledge / Configuration / Change
```

## Work-architecture mechanisms already qualified

- outcome-first work formation;
- Work Object, Transformation, Receiving Context, Work Product, Success Conditions;
- current authoritative reality / professional reference resolution;
- Work Graph;
- Work Units activated when method/capability/dependency/output/interface/authority/assurance/transition/recovery differs materially;
- Human/AI/tool/workflow/existing-process allocation;
- Human learning/stewardship effect where material;
- Working State vs Authoritative State vs Knowledge Capital;
- Capability vs access vs authority;
- assurance matched to claim;
- realization chain to outcome/value;
- local reopen / reintegration / re-assurance;
- institutionalization boundary: reusable Work pattern becomes canonical Operating pattern only through explicit authorized promotion.

## Architecture-evaluation evidence

Seven scenarios did not expose a missing foundation layer/control plane. Two bounded repairs clarified:

1. Work ↔ Operating ownership during institutionalization;
2. Learning proposes/routes change but does not own authoritative mutation outside its domain.

Process proportionality was explicitly supported.

## Next disposition

**RETAIN AS PRIMARY QUALIFIED WHOLE-SYSTEM PRIOR.**

The Next program may replace it, but must first show a material advantage or repaired defect rather than merely an alternative vocabulary.

# 5. Counter-design D — PAOS

## Prior status

Semantically accepted native-surface architecture source; runtime not established by the architecture file.

## Relevant counter-position

PAOS explicitly says ordinary chat/research/document/coding work does **not** require a formal Work Object and rejects a universal Work Object lifecycle.

It uses:

```text
Entry Surface
Context Home
Execution Surface
Return Surface
```

with selective handover and only conditional Project formation.

## Next disposition

**RETAIN AS MINIMUM-COMPLEXITY RIVAL.**

Any Next architecture that introduces F0–F4, Work Engine state, formal Work Objects or portfolio/project objects must demonstrate why latent/conditional semantics are insufficient.

PAOS is a required counterfactual for the compression/generalization test.
