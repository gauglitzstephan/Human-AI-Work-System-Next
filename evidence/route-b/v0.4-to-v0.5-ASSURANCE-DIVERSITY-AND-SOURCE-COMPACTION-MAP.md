## FD-01 — False independent assurance

### Failure mechanism

v0.4 required property-specific, failure-detecting assurance and rejected a second pass with the same contaminated context, but it did not positively require a failure-relevant diversity basis. A fresh thread or different agent using the same evidence, method/model/provider and assumptions could still be mislabeled independent.

### Controlling responsibility

- Requirement: CR-11 claim-matched professional assurance
- Architecture owner: Work Responsibility / Professional Quality and Claim Integrity
- Canonical Source owner: `01-CANDIDATE-CONTRACT.md`, section “Direct, delegated and assurance composition”

### Admitted source rule

An independent-assurance claim must:

1. name at least one failure-relevant diversity basis:
   - different evidence access;
   - different method, model or provider;
   - deterministic check; or
   - qualified Human/domain judgment;
2. explain why that basis can detect the producer's material failure mode; and
3. otherwise classify the activity only as second-pass review.

### Control-admission record

- Exact failure: false independent PASS caused by correlated producer/reviewer error
- Expected benefit: prevent thread or agent identity from being mistaken for failure-detection independence
- Activation: only when the work claims `independent assurance`
- Negative universalization constraint: no default reviewer, second agent, method change or deterministic check; ordinary self-review remains eligible where adequate
- Evaluation/falsifier: an independent-assurance claim without a named detection-diversity basis is a source/carrier conformance FAIL
- Retirement/simplification: simplify or retire this wording only when a supported carrier provides an equivalent verifiable independence property without semantic loss

The rule appears once at the canonical Source owner. Kernel, Adapter and Manifest refer to that owner rather than restating the normative rule.
