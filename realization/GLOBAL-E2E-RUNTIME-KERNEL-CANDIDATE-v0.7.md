## R20 Entry-Dispatch boundary

The revised relation is:

```text
every Human trigger
→ bind legitimate context
→ BOUND continuation | NEW/CHANGED CLAIM
→ if NEW/CHANGED: DIRECT | FORMATION
→ only then substantive Work Functions
```

An existing Parent does not pre-admit new child claims. Material changes to claim/scope/requirements/means re-enter Admission. `DIRECT` remains claim-relative, not complexity-relative; explicit exploration may execute directly as probe-level work.

The candidate does **not** establish behavioral conformance. Global v0.5 remains the active repository-promoted and externally restored Runtime until a separate legitimate transition.
