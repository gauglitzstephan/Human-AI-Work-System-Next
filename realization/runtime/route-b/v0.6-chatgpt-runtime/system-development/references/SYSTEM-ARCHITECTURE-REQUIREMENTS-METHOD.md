# System Architecture / Requirements Method v0.1

**Status:** CANDIDATE METHOD PACK  
**Use when:** a System Development frontier requires architecture/requirements formation, comparison, design or conformance assurance.

## Method objective

Produce the smallest architecture/requirements result sufficient for the current claim without inventing a new system when existing state already owns the need.

## Procedure

1. **Bind claim and boundary** — exact decision/change/evaluation object, intended outcome, scope/scale and current gate.
2. **Recover authoritative baseline** — current requirements, architecture, decisions, runtime constraints, failures and existing valid structures.
3. **Separate requirement from solution** — raw request/proposed component/surface is not automatically a requirement.
4. **Form performance needs** — functional outcome, quality/non-compensatory properties, intended use, authority/state/transition constraints.
5. **Trace ownership** — each material requirement maps to a legitimate architecture owner/mechanism; do not equate concern/view/function with module/agent/store.
6. **Compare routes at one decision level** — preserve/repair/reuse/adapt/compose/build; include simpler/no-action when material.
7. **Check realization** — actual runtime/provider/state/permission/carrier conditions needed to preserve the semantics.
8. **Assure relational integrity** — requirement→owner→mechanism→runtime claim; detect unowned transformation, type collapse, authority contradiction and semantic loss.

## Outputs

Proportionately:
- current baseline and exact delta;
- requirements/performance model;
- candidate route/architecture change;
- traceability to owners/mechanisms;
- unresolved dependencies/assumptions;
- exact supported claim and reopen conditions.

## Failure modes

- architecture-first invention;
- requirement = user wording/proposed means;
- static semantic coverage mistaken for runtime mechanism;
- mixed-level options compared as peers;
- logical distinction reified as persistent module/Project/agent;
- implementation simplicity used to justify semantic loss.
