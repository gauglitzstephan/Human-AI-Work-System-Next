# Real-Use Validation Method v0.1

**Status:** CANDIDATE METHOD PACK  
**Use when:** the installed Runtime is being exercised on genuine professional work and evidence must support or falsify behavioral claims.

## Method objective

Evaluate the actual end-to-end Runtime on real work, preserve evidence outside chat, and localize defects without turning every failure into architecture redesign.

## Procedure

1. Use an **actual work problem** by default; synthetic isolation only when an observed failure cannot be localized and expected information value justifies it.
2. Record case ID/work class, raw trigger, controlling state, actual Runtime/surface/provider context and relevant authoritative sources.
3. Observe whether the system selects a proportional frontier and activates only needed Work Functions/Methods/providers.
4. For any responsibility/environment change record Handoff/Return state and whether parent/authority continuity survives.
5. Record material decisions, Commitment/Authorization/Human Gate/Promotion events separately.
6. Preserve actual Work Product/version and assurance applied; do not infer recipient-readiness/use/outcome from production.
7. Where real use occurs, capture transition/use/performance/mechanism/outcome evidence and attribution limits.
8. Record Human corrections/burden, especially AI-resolvable defects first detected by Human.
9. Score exact dimensions required by the current E2E real-use validation protocol and persist material evidence under `evaluation/e2e-real-use/`.
10. On failure use the RCA/Failure Localization Method and repair the lowest responsible layer; reopen static architecture only on a named material trigger.

## Critical failure triggers

- unowned material transformation;
- required method/control cannot be realized in the intended runtime without semantic distortion;
- illegitimate state promotion/authority transfer;
- Human Gate does not actually stop blocked downstream work;
- handoff amnesia / parent-root drift;
- repeated Human bridging of AI-resolvable system gaps;
- unsupported readiness/outcome claim;
- runtime compression/precedence silently removes material semantics.

## Non-claims

One successful case does not establish universal reliability, professional quality across domains, Quality-in-Use, causal superiority or realized value.
