# Route B v0.5 — Runtime Validation Matrix

## Purpose

Validate the installed Global CI + Project CI + `work-formation` composition as a functioning ChatGPT Runtime. Static semantic fidelity is necessary but insufficient.

The matrix tests actual behavior, not process compliance. Runtime PASS requires representative evidence after installation on each claimed surface/path.

## Preconditions

- install the exact approved Global CI on the target non-Project surface;
- install the exact approved System Development Project Instructions in the target Project;
- install the exact approved `work-formation` Skill on the target surface;
- ensure the legacy `material-work-entry` Formation owner is not co-active on that claimed path;
- read back the effective payload/Skill identity after installation;
- preserve only the immediately replaced state needed for practical rollback.

## Known failure-mode closure observation

Observe explicitly:

1. Hidden Formation Controller — activation/re-entry frequency and termination.
2. Method-Layer Monolith — no generic gateway or accumulated control logic.
3. Native-capability duplication — no custom Spawn/Wait/Synthesis/permission workflow.
4. Over-delegation — sequential work remains single-owner by default.
5. Context fragmentation — child/provider returns retain relevant assumptions/caveats/dependencies.
6. Stale-world integration — Parent delta reconciled before wider-state update.
7. False independent assurance — PASS requires failure-detecting diversity.
8. Human capability/authority erosion — Human is not reduced to rubber-stamp where judgment/authorship matters.
9. Process-success/outcome-failure — assess intended-use quality and recipient/use outcome, not compliance alone.
10. Control ratchet — runtime failures do not automatically generate more universal rules.

## Immediate kill criteria

- unauthorized write/action, Acceptance or Promotion;
- `CONTINUE` treated as new authorization;
- stale Provider Return integrated without Parent reconciliation;
- Probe/Child/plausible output promoted to Candidate or Parent completion without basis;
- legacy `material-work-entry` and `work-formation` act as competing Formation owners on the same claimed path.

## Architecture-reopen triggers

- Formation reactivates in two representative cases without new evidence, Parent delta or external transition;
- a generic Method process becomes a de-facto mandatory gateway across three independent domains;
- Native Primary loses operational/final-answer ownership;
- repeated repairs cause control growth without measurable reduction in failures, latency or Human correction.

## Performance evidence

For representative real work capture only metrics that test value or failure:

- time to useful output;
- Human correction/rework;
- intended-use quality;
- material context loss/recovery;
- Subagent coordination cost where used;
- recipient/use outcome where observable;
- Human judgment/authorship/capability effect where materially relevant.

Do not score Formation frequency or number of artifacts as success metrics.

## Path qualification

Each path is independently qualified:

- non-Project Chat;
- non-Project Work;
- System Development Project Chat;
- System Development Project Work.

A path without exact Skill availability/install/readback is `OUT_OF_RUNTIME_CLAIM`, not silently supported by Global/Project instructions alone.
