# work-formation — Route B v0.5

**Status:** NON-INSTALLED SKILL CANDIDATE  
**Role:** sole Formation Activation Owner  
**Operational owner:** Native Primary, not this Skill  

## Purpose

Use this Skill only to determine whether the current Work Basis is sufficient for the next claim or transition. If it is insufficient and the gap can materially change the legitimate frontier, form only the missing basis, return it to the Native Primary and terminate.

This Skill is not a Material-Work controller, planning layer, method registry, orchestration workflow or domain-execution Skill.

## Activation

Activate substantive Formation only when both are true:

1. the current Work Basis is insufficient for the next claim or transition; and
2. the gap can materially change the Work Function, claim/Candidate status, route class, performance floor, Professional Method need, authority/risk, continuity, intended use/transition, Outcome, strategic-resource allocation, Human capability/future autonomy or Whole-System Economics.

Do not activate merely because work is material/complex, a new turn began, a tool/Subagent returned, uncertainty exists, more analysis is possible or the wider initiative is incompletely specified.

Re-entry after prior sufficiency requires a named new evidence or changed claim, scope, requirement, authority or intended-transition delta that invalidates prior sufficiency. Formation output, termination, ordinary execution progress, elapsed time or tool/Subagent return must not self-reactivate this Skill.

## Formation method

Read and apply `references/FORMATION-METHOD-v0.5.md` as the controlling method source for this Skill. Form only the materially missing portions of Parent/Outcome, next claim/transition, scope, Current Reality/evidence, performance floor, method need, constraints/risk/authority, continuity/assurance/transition and Candidate qualification.

When method class is materially unresolved, use `references/CORE-WORK-FUNCTIONS-AND-METHOD-CONTRACT-v0.5.md` to establish:

`Work Function + Intended Use + Performance Floor + Domain + Evidence Need → eligible Professional Method(s)`

The Work Functions are composable, not stages. Information/Evidence is cross-cutting, not a mandatory research phase.

## Method-library boundary

This Skill does **not** contain the complete professional Method Library and must never become one.

After Formation returns an eligible method class, the Native Primary resolves and executes the method using the shallowest adequate qualified source:

- an already-qualified Domain Skill or Method Pack;
- a fit entry from the repository Method Registry;
- another qualified Project/Drive/repository source;
- current authoritative external reference or professional standard;
- a transparent task-local method with retained limitations;
- qualified Human/specialist contribution when materially required.

If no adequate method can be established, return a weaker readiness/claim or `WAIT/HANDOFF/STOP`; do not substitute generic model plausibility for professional validity.

## Composition boundary

Formation may identify that specialization, parallelism, context isolation, assurance or Human contribution is needed. It does not choose or orchestrate the actual provider topology unless a hard capability/authority constraint leaves only one eligible class.

Native Primary owns direct execution, tools, Subagents, waiting, integration and final answer. The selected Professional Method or Domain Skill owns professional execution. Legitimate Humans/owners retain acceptance, commitment and action authority.

## Termination

Terminate as soon as one disposition is supported:

- `READY`
- `WEAKER_CLAIM`
- `WAIT`
- `HANDOFF`
- `STOP`
- `NO_ACTION`

Return only the minimum Work Basis needed by the Native Primary. It is transient by default and is not an authoritative artifact merely because it was produced.

Do not continue to improve Formation after sufficiency. Do not execute the Professional Method, create a universal handoff/rebind/reviewer chain, manufacture next steps, promote a Probe/Candidate, claim Parent completion or mutate Kernel/Runtime/Project controls during ordinary use.

## Assurance

Identify the property that needs assurance and a failure-detecting assurance class when material. Independent assurance is conditional on correlated-error risk and requires a failure-relevant diversity basis; a fresh thread or separate agent alone does not establish independence.
